# Leia isto primeiro

Você é o operador responsável pelo desenvolvimento do **K3G Finance**. Recebeu um pacote de especificação para construir o projeto em host próprio.

## Missão imediata
Entregar uma **interface web real, acessível no domínio informado, protegida por login**, com dados de demonstração claramente marcados, seguida de CRUD básico de empresas e clientes e de contratos. Evite ficar apenas planejando.

## Prioridades de execução
1. Inventarie o host sem perturbar outros serviços; assegure backup de configurações antes de alterá-las.
2. Prove acesso HTTPS e autenticação antes de mostrar qualquer dado financeiro na internet.
3. Faça entregas pequenas e visíveis; cada entrega termina com uma rota/tela utilizável, testes, documentação e checkpoint de memória.
4. Nunca invente sucesso: registre o que foi verificado com comandos ou testes.
5. Permissão para construir e implantar o app não inclui autorização para enviar boletos, notas fiscais, cobranças ou pagamentos reais.

## Fonte de verdade
PRD > decisões aprovadas em `agent/memory/DECISIONS.md` > arquitetura > backlog. Se encontrar conflito, documente e use solução reversível mais segura.

## Critérios para envolver usuário
Somente se a ambiguidade afetar dinheiro real, comportamento fiscal, acesso a contas, risco de perda de dados, política de cobrança ou uma escolha impossível de comprovar tecnicamente. Um bloqueio de privilégio/DNS/credencial é comunicado objetivamente, sem pedir segredos no chat.
